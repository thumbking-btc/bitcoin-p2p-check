# 체크박스 크기·일관성 교정

## 사용자 요구와 이전 수정의 오류

사용자는 `기존 거래자 우대`를 체크할 때 커지던 행을 **선택 전의 작은 크기로 유지**하라고 요청했다. 이전 수정은 펼쳐진 입력 영역을 항상 배치하여 기본 행까지 키웠다. 선택 전후 높이만 비교한 테스트로는 이 오류를 발견할 수 없었다. 원래 크기와 이웃 체크박스의 규격을 함께 비교해야 한다.

## 교정과 확인 범위

- 모집글의 세 체크박스 행은 모두 44px이며 선택 전후 높이·너비·체크박스 위치·글꼴 크기·굵기가 같다.
- 우대 프리미엄은 선택할 때만 같은 행 오른쪽에 나타난다. 해제하면 숨기고 모집글에도 포함하지 않는다.
- 모바일에서 겹친 패널 테두리와 여백 때문에 선택 항목 폭이 지나치게 좁아지는 문제를 함께 수정했다. 숫자 입력 글꼴은 16px을 유지한다. 좁은 화면에서는 직접 입력하고 데스크톱에서는 기존 증감 버튼도 사용할 수 있다.
- 320·390·768·1280px에서 세 체크박스를 각각 전환하고 실제 기하 정보를 비교했다. 우대 프리미엄의 직접 입력·키보드 증감·모집글 반영과 가로 넘침 없음도 확인했다. 320px 및 데스크톱 캡처를 직접 확인했다.
- 관련 라디오 선택 스타일은 색과 배경만 변경한다. 큰 거래 금액 확인 체크박스도 선택에 따라 내용을 추가하지 않는다. 모든 앱 화면을 전수 검수했다는 뜻은 아니다.

## 검증

- 로컬 build, lint, typecheck 통과.
- Node 277개 통과.
- 관련 브라우저 시험 2개 통과: 기존 320px 입력·포커스·복사·접근성 시험과 새 4개 화면 폭의 규격 비교 시험.
- 로컬 증거: `outputs/validation/compact-checkbox-{build,browser,node}-20261002.log`, `compact-checkbox-320-{off,on}-20261002.png`.
- 배포 대상은 기존 staging이다. 최종 원격 검증과 배포 결과는 해당 커밋의 GitHub Actions 기록으로 확인한다.

앞으로 선택 전후 같다는 조건만으로 UI 수정 완료를 판단하지 않는다. 사용자가 지정한 기본 상태와 이웃의 같은 종류 컨트롤을 기준으로 비교한다.
