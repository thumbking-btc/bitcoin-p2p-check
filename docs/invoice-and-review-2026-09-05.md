## 이 앱에 반영한 판단

| 항목 | 적용 |
|---|---|
| 발급 주체 | 라이트닝 주소의 수취 지갑 서비스에 현재 금액의 인보이스를 요청한다고 설명합니다. |
| 발급과 입금 | 발급 성공 문구에서 금액·만료 확인과 실제 입금 확인을 구분합니다. 자동 입금 확인을 약속하지 않습니다. |
| 결과를 받지 못한 요청 | 서버에서 콜백을 시작했는지 구분해 결과 불명을 전달합니다. 자동 재요청하지 않고, 받는 지갑 확인 후 사용자가 새로 요청합니다. |
| 실패 응답 | HTML 오류 페이지나 과도한 응답을 사용자에게 노출하지 않습니다. 알려진 거절과 발급 결과 불명을 구분합니다. |
| 검증 | 기존 메인넷·서명·고정 금액·만료·메타데이터 검증과 최소 120초 잔여 조건을 유지합니다. |
| 선택 기능 | 지갑 이름으로 기능을 단정하지 않습니다. LUD-12 메모 전달은 결제 지갑 표시 보장이 아니며, 서명된 인보이스 설명을 수정할 수 없습니다. |
| 직접 입력 | 주소 서비스가 발급을 지원하지 않으면 수취 지갑에서 직접 만든 인보이스를 입력합니다. |

LUD-18 필수 신원정보를 임의로 만들어 보내거나, LUD-21 응답 없이 입금을 자동 확정하거나, 중간 수탁 지갑을 두는 기능은 추가하지 않았습니다. 여러 사람의 정산 상태를 관리하는 Split의 저장 구조도 이 앱에 그대로 옮기지 않았습니다.

## 문구와 동작

- 화면 전용 preview에는 작동하지 않는 기록 생성 버튼 대신 전체 기능 검수 링크를 제공합니다. 전체 기능 검수는 기존의 별도 staging Worker·서명 키·저장소를 사용합니다.
- 환경 오류에 “같은 준비 기록을 확인한다”는 안내를 붙이지 않습니다. 기록 요청 결과가 불명일 때만 동일 조건의 재시도가 중복 생성을 방지한다고 설명합니다.
- 카드 준비와 공개의 순서를 실제 동작에 맞춥니다. 준비는 비공개 15분, 공유·저장 성공 후 공개이며 공개 링크는 최대 180일입니다.
- 공개 범위와 링크 종료 방법은 공유 버튼 근처에 모읍니다. 서명 확인 화면에는 기록 무결성과 실제 입금 확인의 차이를 짧게 안내합니다.
- 실제 책임 범위에 관한 법적 결론을 문구로 단정하지 않습니다. 앱이 확인하는 사실과 사용자가 다음에 할 행동을 안내하는 방향입니다.
- 오래된 시세·변경된 금액·만료 임박 인보이스의 공유 차단은 그대로 유지합니다.

## 검수 주소

[전체 기능 검수](https://bitcoin-p2p-check-staging.thumbking-btc.workers.dev/?pwa-review=1)는 운영 서비스와 별도입니다. `pwa-review=1`은 해당 canonical staging에서만 설치·오프라인 시험을 허용하며 기본 staging과 알 수 없는 호스트는 서비스 워커를 활성화하지 않습니다. 다른 출처의 초안은 자동으로 전달하지 않습니다.

브라우저 자동 시험은 환경별 생성 가능 여부, 불명확한 발급 결과와 명시적 재요청, 만료·시세 변경 차단을 확인합니다. 실제 자금 송금과 실제 휴대전화 지갑의 표시 확인은 별도 시험입니다.
