# 선택·전환 UI 크기 점검

기존 거래자 우대 행 교정 후 사용자가 다른 UI에도 같은 문제가 있는지 확인을 요청했다.

## 확인한 문제와 수정

거래 기록 카드에서 라이트닝의 인보이스 직접 입력으로 전환하면 `붙여넣기` 버튼이 입력창에 맞춰 44px에서 104px로 늘어났다. 수취정보 입력 행에서 버튼의 세로 늘림을 해제해 기존 44px 높이와 너비를 유지하고 입력창 상단에 정렬했다. 여러 줄을 입력하는 인보이스 입력창은 원래 높이를 유지한다.

## 비교 범위

- 구매·판매 선택, 모집글·거래 기록 카드 선택: 선택 전후 컨트롤 크기 유지.
- 모집글 전송 방식 세 항목, 수취정보 전송 방식 두 항목: 선택 전후 크기 유지. 수취정보 설명의 줄바꿈으로 배경 높이가 어긋날 가능성도 의심했으나 검사한 화면 폭에서는 재현되지 않아 수정하지 않았다.
- 고액 거래 확인: 체크박스 18px 유지, 체크 전후 알림 영역 크기 유지.
- 계산 기준·제작자 접기/펼치기: 제목 행 크기 유지. 본문이 펼쳐지며 문서가 길어지는 정상 동작은 문제로 분류하지 않았다.
- 기존 모집글 체크박스 회귀 검사도 함께 통과.

305·320·390·520·521·768·1280px의 Chromium에서 비교했다. 305px는 320px 창에 15px 스크롤바가 있는 경우의 콘텐츠 폭도 점검하기 위한 값이다. 좁은 화면과 데스크톱 수취정보 영역은 캡처도 직접 확인했다. 네트워크 대기·만료·모든 오류 조합과 실제 휴대전화 OS별 전수 검사는 이번 범위가 아니다.

## 검증 증거

`e2e/hardening.spec.ts`의 `selection controls keep their bounds and adjacent controls align`은 수정 전 104px 버튼을 실패로 검출한다. 수정 후 버튼이 원래 크기를 유지하는지, 입력창 상단에 정렬되는지, 선택 컨트롤과 제목 행 크기 및 가로 넘침이 유지되는지를 비교한다.

로컬 로그와 캡처는 `outputs/validation/ui-consistency-*20261002.*`에 보관한다. 최종 staging 배포는 수정 커밋의 전체 GitHub Actions 검증을 거친다. 이 검사를 모든 UI에 문제가 없다는 보증으로 확대하지 않는다.
